# 轨迹、GPS状态与2M/8M有效里程计算

读取 `input` 目录中的轨迹文件，解析经纬度、时间、GPS解算状态和基线长度
（`$GPFPD` 的 baseline 字段），自动标记异常，并输出
**GPS覆盖里程 / 2M里程 / 8M里程 / 实际有效里程**。

## 支持的输入格式（自动识别）

| 格式 | 首行特征 | 时间 | GPS状态来源 | 2M/8M来源 |
| --- | --- | --- | --- | --- |
| `$GPFPD` | `$GPFPD,...` | GPS周+周内秒 | 第16个字段（1/2/11/12稳定） | 第13个字段 baseline |
| `$GPGGA`/`$GNGGA` | `$GPGGA,` | 当天秒数 | 第7个字段定位质量（1/2/4/5稳定） | 无（不参与2M/8M） |
| CSV | `时间戳,纬度,经度,高度[,状态,基线]` | 绝对时间戳 | 可选第5列（两套稳定码取并集） | 可选第6列 |

缺少 GPS 状态字段的文件不会被当成“正常”，而是直接标记异常
“缺少GPS状态字段，无法计算GPS覆盖里程/实际有效里程”。

**GPS 覆盖里程与 2M/8M 无关**：只要相邻两点状态稳定、校验和正确、且不是时间异常/跳点
就计入。所以纯 GGA/CSV 轨迹（没有 baseline）也能算出 GPS 覆盖里程，
只有 2M/8M 里程会因缺 baseline 为 0。AP18 惯导数据就属于这种情况。

## 判定口径

**GPS覆盖**：`$GPFPD` 状态为 `1/2/11/12`（`0`初始化、`3`纯惯性视为不稳定），
GGA 定位质量为 `1/2/4/5`；同时 NMEA 校验和必须正确。

**2M/8M 数据**：baseline 分别接近 `2.0m` / `8.0m`，默认允许偏差 `0.5m`。
2M 与 8M 切换的那个相邻段不跨类别累计里程。

**逐相邻段异常标记**（每一段都会在报告的明细里写明原因和是否计入）：

| 情况 | 处理 |
| --- | --- |
| 时间戳重复/倒退 | 标异常，该段不计入任何里程 |
| 时间间隔 > 5 分钟 | 切分为新行程，该段不计入任何里程 |
| 轨迹跳点（超过 150km/h 对应距离） | 标异常，该段不计入任何里程 |
| 基线长度不属于 2M/8M | 标异常，不计入 2M/8M 里程 |
| GPS状态不稳定 | 2M/8M 数据里程照计，不计入 GPS覆盖/实际有效里程 |
| NMEA 校验和错误 | 2M/8M 数据里程照计，不计入 GPS覆盖/实际有效里程 |
| 缺少GPS状态字段 | 2M/8M 数据里程照计，不计入 GPS覆盖/实际有效里程 |

**文件级异常（缺一个即异常）**：2M 和 8M 必须同时存在，任一缺失（或该类的段全部被判异常）
即标记异常；此外 GPS状态整体缺失、校验和错误、时间异常、跳点、实际有效里程为 0
或占比过低（< 30%，见 `config.MIN_EFFECTIVE_MILEAGE_RATIO`）也会标记异常。

**整批异常**：一次分析的批数据里 2M 里程或 8M 里程任一为空、实际有效里程为 0，
或存在任一异常文件，即整批判定为异常（原因写在汇总里）。

## 里程定义

| 里程 | 含义 |
| --- | --- |
| GPS覆盖里程 | 两端 GPS 覆盖且校验和正确的相邻段长度之和 |
| 2M里程 / 8M里程 | 两端同属 2M（或 8M）且未判为时间/跳点异常的相邻段长度之和 |
| 实际有效里程 | GPS覆盖 且 属于2M/8M 的相邻段长度之和（= GPS覆盖且2M + GPS覆盖且8M） |

**实际有效里程就是最终要的口径**：只有 GPS 状态稳定、校验和正确、
且数据确实来自 2M 或 8M 的那部分轨迹才计入。

## 使用方法

整个目录批量分析（2M 与 8M 文件都放进去，缺一个会整体标异常）：

```powershell
python main.py --input input --output output
```

单独分析一个文件：

```powershell
python main.py --file your_data.txt
```

基线容差不是 `0.5m` 时可以在命令行覆盖：

```powershell
python main.py --baseline-tolerance 0.2
```

## 输出

- `output/analysis_<文件名>.csv`：单文件汇总、GPS状态分布、解析/校验异常行、
  逐相邻段明细（含距离、是否计入、异常原因）。
- `output/summary_all_files.csv`：整批 2M/8M 完整性判定与各文件里程汇总。

稳定状态码、基线容差、跳点阈值、时间断点阈值、有效里程占比阈值都在 `config.py` 中调整。

## AP18 惯导数据（pcap → GGA → 里程）

`probe_ap18.py` 用于探查 AP18 pcap 的 UDP 载荷；AP18 的 pcap 里承载的是
`$GNGGA`/`$INGGA` 定位语句（含经纬度、定位质量、卫星数、HDOP），**没有 baseline**，
所以只能算 GPS 覆盖里程，2M/8M 里程为缺失。

把 GGA 转成标准 CSV 放进 `input/` 后（列：`时间戳,纬度,经度,高度,定位质量,基线`），
用 `main.py --file` 即可得到逐段明细。生成单日 HTML 汇报：

```powershell
python make_html_report.py
```

输出 `output/20260917_LYNK01_AP18_report.html`（自包含，只读扫描设备目录）。
